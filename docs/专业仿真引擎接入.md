## 本机启动

在项目目录运行：

```powershell
./scripts/setup-simulation.ps1
./scripts/start-platform.ps1
```

前端为 `http://127.0.0.1:4186/?scene=room&center=simulation`，求解服务为 `http://127.0.0.1:8001`，交互 API 文档为 `/api/simulation/docs`。支持双击根目录的启动算电协同.cmd，按需安装本项目隔离的 Python 依赖，再启动两个服务。

Python 依赖位于 `.venv-sim`，本机测试环境为 Python 3.12。Windows 使用 requirements.lock.txt；其他系统使用 requirements.txt 安装。运行数据在 `.solver-data`，均已加入 Git 忽略规则。`-Build` 构建前端，并仅在没有排队/运行任务时重启本项目求解服务，不中断现有计算。日志在 `.solver-data/api.*.log` 和 `.solver-data/frontend.*.log`。

## Linux 引擎环境

本机没有配置 Docker/WSL，未自动启用 Windows 虚拟化或重启系统。有可用 Docker Linux 容器环境后运行：

```powershell
./scripts/setup-simulation.ps1 -Containers
```

构建 `aidc-openfoam:2312` 和 `aidc-fenicsx:0.9.0`。基础镜像来自 OpenCFD 与 FEniCS 官方镜像。任务运行时禁用容器网络，限制 2 CPU、4GB 内存、256 个进程；仅后端代码挂载为只读，任务目录可写，不挂载项目其他目录及环境配置。已配置原生 Linux 引擎时也支持本地命令执行；OpenFOAM 原生环境需要先加载其 bashrc 并使求解器位于 PATH。

容器构建配置和算例生成已提供，但本机没有执行 docker build、CFD 收敛测试、有限元制造解测试或网格独立性验证。这些必须在 Linux 引擎环境就绪后补做，才能确认对应数值任务的适用性。

## 模型和物理假设

前端从当前设备库和端口连接生成快照，包含设备位置、额定容量、启停、供电开关、风冷/液冷、负载与风水侧热量。提交任务时冻结快照。前台机房/园区视图按变化同步模型（最多每 4 秒一次），工程工作台打开后也会同步；API 返回最后同步时间。读取的是最后一次同步的模型，不是外部现场遥测。

pandapower 将 A/B 路分别建模；默认 UPS 并联模块共享母线，显式改接线后按所选连接建模。UPS 为稳态通过支路、容量检查和附加损耗，不模拟电力电子开关、完整 UPS 控制暂态或电池放电暂态。电缆长度由位置估计，电阻、电抗、额定载流量、并联数和变压器铭牌采用可编辑假设。机电辅助支路的电缆按当前功率加余量估计。完整供电校核仍需现场单线图、实际导线和保护参数；没有宣称接入 ETAP 或完成保护选择性计算。

PyPSA 以电等效 IT 功率表示算力需求，采用用户配置的电价与峰谷系数。不可迁移负载固定到各节点，灵活部分通过计算负载池分配，受 IT 容量、总迁移功率、节点购电上限和总购电上限约束。储能充放效率各为 95%，最低 SOC 可调，首末 SOC 相等并固定为 50%；同一小时不得同时充放电。目标包括电费及迁移成本，没有连接真实算力作业调度器、电力交易或现场储能控制器。

OpenFOAM 房间算例使用 96×61×8.5m 计算域，采用当前机柜与 CRAC 位置构造等效体热源、阻力、风机和换热源。风水热量来自当前资产快照，液冷捕获上限可调，不把未供电设备的名义需求当作热源。粗网格不解析机柜内部，不以渲染用 GLB 直接充当完整工程流体几何。局部 CHT 为 0.6×0.2m 空气/板/水基准组件，并按入口 Reynolds 数选择层流或 kOmegaSST。该模式是双流体与固体的共轭换热模型；整机房模式是等效源模型，不应混同为逐服务器全细节共轭仿真。

FEniCSx 组件采用用户给定尺寸、导热系数、局部表面热源和水风换热系数，侧面绝热。组件标签可关联冷板、背板或 CDU 板，几何仍是参数化板，不是已导入的厂商微通道 CAD。求解后检验 PETSc 收敛与表面热平衡。

## 智能体接口

MCP stdio 启动命令：

```powershell
./.venv-sim/Scripts/python.exe -m backend.mcp_server
```

启动目录为项目根目录，默认连接本机 8001 端口。可通过 AIDC_SIM_URL 配置同一受控求解服务地址。工具包括：

- list_simulation_engines：检测真实引擎运行状态。
- get_current_asset_model：读取最后同步的模型与同步时间。
- submit_simulation：提交求解任务，返回异步任务编号。
- prepare_simulation_case：生成可执行的算例包。
- get_simulation_job：查询任务、指标、校核、日志及产物。
- cancel_simulation_job：取消任务，保留输入与日志。
- read_simulation_artifact：读取不超过 2MB 的 JSON/CSV/日志；二进制或更大的结果返回下载地址。

例如 submit_simulation(engine="pandapower", parameters={"analysis":"power_flow_short_circuit"}) 会使用最后同步的设备模型。输入均经 Pydantic 字段、范围和网格规模校验，不提供任意代码或 shell 命令执行入口。

## 任务与结果

每个任务保存 request.json、status.json、solver.log 和成功后的 result.json，另有网络模型、CSV、NetCDF、温度场或 XDMF 文件。输入以 SHA-256 标识，结果记录引擎版本、适配器源码哈希与耗时。任务状态区分 prepared、queued、running、succeeded、failed、cancelled；只有真实求解进程成功且收敛后才能成为 succeeded。数值收敛不代表所有工程约束通过，未供负载或超限仍显示在结果中。

求解与前端渲染分离，最多同时运行两个作业，最多 12 个排队/运行任务，任务可取消并有时间上限。重启服务后保留历史结果，将未完成任务标记为中断。结果图层关联输入模型版本；设备、负载或工况改变时，旧结果隐藏并提示重算。电力结果可在机柜顶部显示，温度场提供高度切片与计算速度向量，不用装饰粒子替代数值向量。
