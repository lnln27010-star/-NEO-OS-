# 同场景运营测试

## 使用路径

默认园区 → “进入数据厅”（也可双击测试建筑） → 顶部“运营仿真” → 选择工况和负载 → “运行测试” → 点击告警定位机柜 → 查看同一时刻的设备详情 → “恢复基线”。

| 入口 | 实际去向 |
| --- | --- |
| 顶部“机房”、园区“数据厅”、“进入数据厅”及浏览模式双击测试建筑 | `sceneScope = room`，同一个 Northbridge BIM 视口切到室内浏览视点 |
| 顶部“运营仿真”、园区“启动运营仿真”、左侧“场景仿真” | `sceneScope = room`、`twinMode = operate`，同一视口切到运营视点并显示机柜色带、结果与告警 |
| “浏览”或左侧“数字孪生设计器” | 回到当前空间的浏览模式，保留构件选择、剖切和相机控制 |
| “布局编辑（旧方案）” | 独立的 `sceneScope = layout`，显示原 A2 布局工具、资产库、属性检查器及保存/校核操作 |

`campus` 和 `room` 共用一个 `CampusViewport`；新版机房不会载入旧 A2 的资产库和检查器。旧布局实例及本地保存数据继续保留，新运营测试不读取它们计算，也不回写它们。

运营仅适用于加载成功的 Northbridge 测试模型。模型未就绪、加载出错或导入未绑定设备的本地 GLB 时，面板显示不可用及恢复入口，不把测试厅的指标或告警套用到导入模型。

## 一份状态驱动四种呈现

`src/operationsModel.ts` 的 `RACKS` 是唯一机柜注册表，共 A–H 排、每排 24 柜，ID 从 `R-A01` 到 `R-H24`。它同时提供位置、配电支路与冷却回路归属。`EngineeringSite.tsx` 按此表生成机柜几何，运营命中区域、选择框和相机定位也按此表取坐标。

`calculateFrame({ scenario, load, seconds })` 一次计算完整结果，`useOperationsStore.ts` 保存该 `frame`。以下呈现共同消费当前帧，不能各自生成随机数或保留独立时间轴。

| 呈现 | 同帧数据 |
| --- | --- |
| 三维机柜顶部色带 | `frame.racks`、`frame.feeders` 与当前温度/供电图层，经 `rackColor` 计算 |
| 总览 | 同帧机柜聚合功率、最高进风温度、失电数量和告警数量 |
| 机柜及支路详情 | `selectedRackId` 对应的同帧机柜，以及该机柜所属支路 |
| 告警列表 | `frame.alerts`；每条告警携带注册表内的 `rackId` |

点击三维机柜可选择对象；机柜下拉框、支路下拉框、详情“定位”及告警按钮可同时定位相机。告警定位会滚动到设备详情，保持当前测试时刻和运行状态；需要固定时刻检查时先暂停。列表按严重告警优先、同级机柜编号排序，显示级别文字，可滚动访问全部告警。运营模式隐藏仅用于浏览的配置和构件目录工具；恢复视点直接返回机柜总览。

## 时间轴与恢复

- 三种工况均覆盖 T+0 至 T+120 s。运行时每个 1,000 ms 浏览器定时器回调推进 2 s；这是约 2 倍速的演示时间，不是现场实时时钟，也不补偿浏览器后台计时节流。
- “暂停测试”冻结当前帧，“继续测试”从该时刻继续。拖动时间轴以 2 s 为界面步长回看并暂停；到 T+120 s 时状态为“已完成”。
- 完成后“重新运行”从 T+0 开始，保留当前工况和负载。更改工况或负载会回到 T+0 和“待运行”，重新计算基线时刻；供电故障默认切到供电图层，其余工况默认切到温度图层。
- “恢复基线”恢复正常工况、70% 负载、T+0、温度图层和“待运行”；当前选中机柜保留。
- 切换结果图层、选中机柜或定位相机不改变测试时间。离开运营模式、切换空间层级、模型不可用或视口卸载会自动暂停；返回运营后由用户继续运行。

## 测试假设与边界

`NB-OPS-1.0` 是自行编写、确定性的合成测试模型，相同输入得到相同结果。它未接入 OpenFOAM、OpenDSS 或现场遥测，未做工程标定；结果只验证交互、对象绑定和数据一致性，不构成生产级工程结论、正式 DSX 集成或 NVIDIA 认证。

- 功率以每柜 120 kW 为计算基准，负载输入范围为 30–100%，再叠加固定列差异和小幅周期扰动；120 kW 不是计算值的硬上限。
- 电流采用三相平衡近似 `I = P / (√3 × V × PF)`，公式中的 P 使用 W，V 为线电压 415 V，功率因数为 0.98。每排对应一个 RPP，测试容量为 2,600 kW；负载率大于 100% 时保留真实计算百分比，不截断。
- 液冷承担 87% 的机柜功率对应热量，基线每柜流量为 120 L/min，供水为 24 °C。按水密度约 1 kg/L、比热 4.186 kJ/(kg·K) 使用 `Q = ṁ × cp × ΔT` 计算回水，流量由 L/min 换算为 kg/s。该近似未模拟泵曲线、管网压降或流量分配。
- 进风温度是负载、列位置及故障增长量的集总近似；排风温升按余下 13% 热量、固定空气质量流量 1.65 kg/s 和比热 1.006 kJ/(kg·K) 估算。没有求解空间 CFD 温度场或设备保护策略。

| 工况 | 注入与作用范围 |
| --- | --- |
| 正常运行 | 全程无故障；高负载仍可能触发支路超载阈值 |
| CDU-02 流量下降 | T+20 s 标记故障生效，只影响 E–H 排的 96 柜；随后按 18 s 时间常数渐变，流量趋向基线的 35%，进风附加温升趋向 12 °C。T+20 s 的增长量为零，告警随阈值达到后出现 |
| RPP-C 断开 | T+20 s 起 C 排 24 柜立即失电，功率和电流归零；假定单路供电且无自动倒换。该场景不模拟上游故障电流、保护配合或热惯性 |

温度色带以进风温度分为低于 30 °C、30 至低于 35 °C、至少 35 °C；流量低于 65 L/min 也可触发冷却预警，因此温度色带与告警严重度不是一一对应。供电色带区分供电正常、支路超载和失电。所有色彩解释均有图例或文字/数值，机柜面板上的静态指示灯不代表运营结果。

## 回归校验

运行 `node scripts/test-operations.mjs` 可校验 192 个唯一 ID、确定性、聚合功率、故障时序与范围、结果着色、超载率、暂停、时间轴、选择/定位状态、重置和完成后重跑。该脚本验证计算与状态逻辑，不代替浏览器交互验证；构建命令为 `npm run build`。

2026-10-08 本轮回归已通过上述脚本，并在浏览器复核以下路径：新版机房未出现旧 A2 资产面板；70% 负载冷却工况在 T+120 s 显示 96 柜告警，告警、详情和图例时间一致，告警可定位 `R-E01`；配电故障显示 24 柜失电；主动暂停和离开视图自动暂停有效；进入新版流程未改变原有旧方案保存数据。以上覆盖当前测试模型和本轮交互，不表示已验证任意导入模型或真实设备。

收尾修复复核：冷却工况 T+48 s 的 96 条告警全部可访问，8 条严重告警排在前面，首项 `R-E23` 可定位并显示同帧详情；直接点击三维机柜成功选中 `R-H13`。导入项目内 `server_rack.glb` 后运营面板明确不可用，设备详情和告警列表均不显示；恢复 IFC 场景后可继续使用测试。700px 预览中的旧方案入口文字保持可见。浏览器控制台未记录错误，生产构建通过（仍有既有大体积 JS 包提示）。
