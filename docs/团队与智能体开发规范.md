# NEO-OS 智能体开发基线（v1）

本规范适用于所有参与开发的智能体。目标是让不同智能体提交的代码能接在一起，同时保留后续调整技术选型的空间。以仓库当前实现为起点，不要求为了符合规范而一次性重写旧页面。

## 统一选型

| 范围 | 基线 |
| --- | --- |
| 前端 | React 19 + TypeScript strict + Vite 8；跨页面状态沿用 Zustand。 |
| 业务 UI 组件 | **Ant Design 6** 作为以后新增表单、表格、弹窗、筛选等业务页面的统一组件库。通过一处 `ConfigProvider` 配置深色/浅色主题和品牌色。当前仓库尚未安装 Ant Design；首次使用时统一接入并更新 `package-lock.json`。现有页面不强制迁移。 |
| 地图与三维 | 沿用项目现有高德地图、MapLibre、Three.js / React Three Fiber。地图控件、机房模型、场景工具条可继续使用项目定制 UI，但颜色、字体、间距与主题保持一致。图标统一用现有 `lucide-react`。 |
| 样式 | 以运行中的 `src/styles.css` 和 `src/useVisualTheme.ts` 为主题基准。Ant Design 通过主题 token 适配，不在各页面大量覆盖组件内部 DOM；公共定制样式集中维护。`design-system/computepowertwin/MASTER.md` 是历史参考稿。 |
| 后端 | Python 3.12 + FastAPI + Pydantic v2；保留 `/api/platform/*` 业务接口和 `/api/simulation/*` 求解接口。 |
| 数据库 | 当前统一使用 SQLite 和现有 Repository，开发数据放 `.solver-data/`。正式多用户部署如需 PostgreSQL，先设计迁移，再统一切换。 |
| 工程计算 | 复用现有 pandapower、PyPSA、OpenFOAM、FEniCSx 适配器；界面估算与真实求解分开标识。 |

Ant Design 6 支持 React 19，并可用 `ConfigProvider` 的主题 token 适配现有深浅色界面，见[官方版本说明](https://ant.design/components/changelog/)与[主题文档](https://ant.design/docs/react/customize-theme/)。选型意味着**新增业务控件优先共用这一套**；场景可视化可做必要的定制。不要在单个页面再引入另一整套组件库、CSS 框架或图标库。

## 开发约束

1. **先看现有实现。** 开始任务前读 `AGENTS.md` 和相关模块，尽量沿用现有数据模型、API、状态与组件。新功能按业务模块组织，避免把实现不断追加到 `src/App.tsx`、`src/components/CenterWorkspace.tsx` 或 `backend/api.py` 这些入口文件。
2. **前后端契约同改。** API 新增或修改字段时，同时更新 Pydantic 校验、前端 TypeScript 类型、调用代码及相关测试。字段名要体现单位；错误、空数据、加载中都应有明确状态。
3. **数据要有出处。** 电价、政策、园区、设备铭牌、测点、投资参数和求解输入标明来源、适用时间、单位及“实测/已核实/引用/假设/缺失”状态。缺数据不能伪装成真实数据；省级参考值不能直接当成项目到户价。
4. **计算要可复核。** 投资测算保留公式和假设；专业仿真记录输入版本、引擎及结果。引擎未就绪就显示不可用，不能生成看似真实的替代结果。
5. **保留体验一致性。** 新页面同时检查深浅主题、导航、基本键盘操作、加载失败和空状态。大型地图、BIM、三维和求解资源按需加载，避免切换场景白屏。
6. **变更要可复现。** 新增依赖同步锁文件；数据库结构变更提供可重复执行的迁移；不提交 `.env*`、`.solver-data/`、虚拟环境、构建产物、真实客户资料或未经授权的图纸。
7. **提交前验证相关路径。** 前端代码至少运行 `npx tsc -b --pretty false`；业务规则运行对应测试；影响生产构建时运行 `npm run build`。后端代码运行相关 `backend/tests/` 测试。文档改动检查链接和格式即可。

每次智能体交付简要说明：**改了什么、验证了什么、仍有哪些真实数据或运行环境限制**。若某项约定妨碍具体需求，先在本规范中记录调整原因和新选型，再让后续任务遵循新版规范。
